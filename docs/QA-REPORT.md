# QA-отчёт BeamHub 0.13.9

- **Дата:** 19.11.2026
- **Версия:** 0.13.9 (`core/version.py`), сборка из рабочего дерева: изменены `app.py`,
  `core/db.py`, `core/tkui.py`, `core/version.py` (0.13.8 → 0.13.9); проверялась именно эта
  сборка, а не последний коммит.
- **Что проверялось:** новое в 0.13.9 — чип «проверенные», метка RU на карточках русских модов,
  полный EN-перевод страницы мода и переключение языка без закрытия страницы; регрессии всех
  экранов и кнопок (каталог, сборки и страница сборки, подбор мода, библиотека, обновления,
  загрузки, настройки, профиль, статистика, админка, модерация, отзывы, обсуждение), переходы
  «назад», загрузка картинок и пустые состояния; API `/api/mods?verified=1`, кривые параметры
  и `/api/img` с битым адресом.
- **Что не менялось:** `core/` и `app.py` — только чтение; временные базы и папки — в `%TEMP%`
  (`qa139-*`), порты 9270+; после прогона пробы и процессы удалены.

## Как проверялось

1. **API-прогоны** на двух независимых свежих копиях `seed/beamhub.db` (порты 9270, 9271):
   `bootstrap()` + `Server` без окна, `BEAMHUB_DATA`/`BEAMHUB_DB` в `%TEMP%`, папки модов и
   загрузок — там же. 66 проверок на прогон: `/api/ping`, `/api/state`, полная выдача
   `/api/mods?verified=1` по 120 записей (сверка с SQL), `img=1`, `verified=1&img=1`, два десятка
   кривых query-параметров, 12 вариантов `/api/img` (пустой, не-URL, ftp, localhost, `[::1]`,
   несуществующий домен, битый `%`, кириллический хост, публичный 404), POST-регистрация и
   `/api/auth/me`.
2. **Прогоны окна (Tk)** — с настоящим `mainloop`, окно 1400×920, восемь независимых прогонов
   (порты 9272, 9273, 9274, 9275, 9276, 9277, 9278, 9279) на разных temp-базах. Каждый сценарий
   поднимал `app.bootstrap()` + `Server` + `tkui.App`; `os.startfile`/`webbrowser` перехвачены,
   `messagebox` — заглушки, поэтому браузер не открывался, диалоги не блокировали прогон. Для
   детерминированной проверки картинок в `img-cache` заранее лежали четыре обложки, остальные
   грузились из сети либо оставались плейсхолдерами.
3. **Данные для экранов:** первый локальный игрок (`admin`), официальные сборки после
   `bootstrap()`, своя черновая сборка из двух модов, комментарий и оценка от второго игрока.
   На странице отзывов проверены видимость комментариев вошедшему, поле ввода, отправка из UI,
   «Ответить» и возврат «Назад» на страницу сборки.
4. **Повторяемость:** каждый дефект ниже подтверждён двумя независимыми прогонами (для UI —
   разные temp-базы и порты; для API — 9270/9271). Для дефекта 3 дополнительно использован
   реальный клик по чипу (`<ButtonPress>/<ButtonRelease>`), чтобы проверить не только прямой
   вызов обработчика.

## Major

### 1. EN-перевод страницы мода переписывает описания модов (`мод` → `v`) и не откатывается

- **Экран:** страница мода → переключение языка на English (и обратно).
- **Что не так:** `App._translate_ui` (`core/tkui.py:713-799`) применяет `i18n.tr()` ко всем
  `Label` и текстам `Canvas`, не отличая подписи интерфейса от пользовательского контента.
  В `SUBS` (`core/i18n.py:335`) есть правило `(" мод ", " v")`, поэтому в EN-режиме описание
  мода «… — мод среднего качества …» превращается в «… — vсреднего качества …». В `seed` под
  это правило попадают 140 описаний; названия модов с отдельным словом «мод» тоже переписываются.
  При возврате на RU описание не восстанавливается: условие отката (`core/tkui.py:753`) требует
  точного совпадения с `i18n.EN.get(original)`, а для подстрочных замен его нет.
- **Как воспроизвести (9273/9277, разные temp-базы):** открыть мод `mg:161165` («Saturn Aura XR…»),
  нажать English. В дереве страницы один и тот же `Label` описания: было
  `… — мод среднего качества …`, стало `… — vсреднего качества …` (`desc_changed=true` в обоих
  прогонах). После возврата на RU текст остаётся `vсреднего`. То же с плашкой
  «Такой же мод есть ещё на: …» → «Такой же vесть ещё на: …».
- **Ожидаемое поведение:** описание и название мода — данные, а не подписи; в EN они должны
  остаться без изменений (или переводиться отдельным полем, а не заменой подстрок).
- **Важность:** major — портится читательский контент карточки и страницы мода, причём откат
  языка не лечит.

### 2. Переключение EN → RU оставляет половину страницы на английском

- **Экран:** страница мода, кнопка языка EN → RU.
- **Что не так:** откат `_translate_ui` (`core/tkui.py:749-754`) срабатывает только там, где
  русский текст был заменён точной записью из `EN`. Строки, переведённые через `RULES`/`SUBS`,
  после обратного переключения остаются английскими: «File», «file is valid»,
  «declared «0.40.x», installed «not detected»», «with installed mods — none found», «10 d ago»,
  «Cars · duplicate · 2». Восстанавливаются только «Конфликты», «Похожие моды»,
  «проверено BeamHub».
- **Как воспроизвести (9273/9277):** открыть мод, включить English, затем вернуть русский.
  В обоих прогонах в текстах страницы остаются перечисленные английские подписи, а описание —
  искажённое (`vсреднего`).
- **Ожидаемое поведение:** после возврата на RU все подписи снова русские, описание —
  исходное.
- **Важность:** major — обратное переключение языка не работает, страница остаётся
  полупереведённой.

### 3. Фильтр «проверенные» теряется на стр. 2 и «Показать ещё»

- **Экран:** каталог → чип «проверенные» → пагинация.
- **Что не так:** `goto_page` (`core/tkui.py:1385-1392`) и `load_more` (`core/tkui.py:1407-1414`)
  собирают параметры заново и не добавляют `verified=1` (в отличие от `reload`). Первая страница
  фильтруется, но вторая и «Показать ещё» запрашивают непроверенный каталог; счётчик прыгает
  обратно на 2165, хотя чип остаётся включённым.
- **Как воспроизвести (9272/9276 — `goto_page(2)`, 9278/9276 — `load_more`):** каталог 2165 →
  клик «проверенные» → 2135. Затем `goto_page(2)` → счётчик «2165 модов · стр. 2», `total=2165`;
  `load_more` → 48 карточек, `total=2165` (в 9276 с включённым «с обложкой» — 2139). В обоих
  случаях `filter_verified` остаётся `true`.
- **Ожидаемое поведение:** фильтр применяется ко всем страницам и к «Показать ещё»; счётчик
  остаётся 2135.
- **Важность:** major — новый фильтр работает только на первой странице и молча сбрасывается.

### 4. `/api/img` на битый адрес отдаёт 404/500 (`NameError: Path`) вместо 400

- **Экран:** API `/api/img?u=…` (картинки каталога и страницы мода).
- **Что не так:**
  - несуществующий домен (`http://nonexistent.invalid/a.png`) → `404` с текстом
    «Адрес картинки ведёт в локальную сеть»: `app.py:492` ищет `"адрес"` с маленькой буквы,
    а сообщение начинается с «Адрес»;
  - публичный, но битый/недоступный адрес (`http://example.com/%zz`,
    `http://пример.рф/а.png`, `http://example.com/no-such-image-qa139.png`) → `500
    {"error": "name 'Path' is not defined"}`. В `core/http.py:107-136` функция
    `_fetch_with_curl` использует `Path(temp_path)` (`:127`), но `Path` не импортирован;
    ошибка вылезает на любом сбое urllib.
- **Как воспроизвести (9270/9271, обе базы):** `GET /api/img?u=http://nonexistent.invalid/a.png`
  → 404; `GET /api/img?u=http://example.com/%zz` → 500 `name 'Path' is not defined`;
  `GET /api/img?u=http://example.com/no-such-image-qa139.png` → 500. Пустой `u`, `not-a-url`,
  `javascript:`, `ftp:`, `127.0.0.1`, `localhost`, `[::1]` корректно дают 400.
- **Ожидаемое поведение:** любой битый/недоступный адрес картинки — 400 с коротким текстом,
  без внутренних имён исключений.
- **Важность:** major — API отдаёт 500 и раскрывает внутреннюю ошибку; по заданию битый адрес
  должен давать 400.

## Minor

### 5. Чип «проверенные» не показывает активное состояние

- **Экран:** каталог → ряд «ФИЛЬТРЫ» → «проверенные».
- **Что не так:** `_paint_chips` (`core/tkui.py:649-651`) перебирает только `game`, `image`,
  `fav`; `verified` в списке нет, поэтому `_paint_chip` для нового чипа никогда не вызывается.
  После клика переменная `true`, каталог фильтруется, но `_bg` остаётся `#171a22`, `_border` —
  `#232734`, как у выключенного. Для сравнения «с обложкой» после клика получает `#33200f`.
- **Как воспроизвести (9272/9276/9278):** клик по «проверенные» → `filter_verified=true`,
  счётчик 2135, `chip._bg=#171a22` и `chip._border=#232734` до и после; у «с обложкой» —
  `#33200f`. Реальный `<ButtonPress>/<ButtonRelease>` даёт тот же результат.
- **Ожидаемое поведение:** активный чип подсвечен так же, как «с обложкой».
- **Важность:** minor.

### 6. «Сбросить фильтры» не снимает «проверенные»

- **Экран:** каталог → пустое состояние «Ничего не найдено» → «Сбросить фильтры».
- **Что не так:** `_reset_catalog` (`core/tkui.py:1295-1307`) сбрасывает `query`, `category`,
  `filter_game`, `filter_image`, `filter_fav`, но не `filter_verified`. После сброса каталог
  остаётся отфильтрованным (2135), хотя пользователь ждёт все 2165.
- **Как воспроизвести (9272/9276/9278):** включить «проверенные» (2135), вызвать
  `_reset_catalog()` → `filter_verified` остаётся `true`, счётчик 2135; повторный клик по чипу
  вручную возвращает 2165.
- **Ожидаемое поведение:** сброс снимает все чипы, включая новый.
- **Важность:** minor.

### 7. `limit=-5` отдаёт все 2165 модов, обходя лимит 120

- **Экран:** API `/api/mods`.
- **Что не так:** `app.py:393-394` делает `min(120, _safe_int(limit, 48))`, но не ограничивает
  снизу. При `limit=-5` SQLite трактует отрицательный `LIMIT` как «без ограничения», и ответ
  содержит все 2165 записей вместо максимум 120.
- **Как воспроизвести (9270/9271):** `GET /api/mods?limit=-5` → 200, `total=2165`,
  `len(items)=2165`; при `limit=0` — 200 и пустой список.
- **Ожидаемое поведение:** `limit` зажимается в 1…120 (или 400).
- **Важность:** minor (контракт и нагрузка, не 500).

### 8. В EN-каталоге «проверенные» и «ФИЛЬТРЫ» остаются русскими, «Скачать» на карточках не переводится

- **Экран:** каталог → English.
- **Что не так:** новых строк «проверенные» и «ФИЛЬТРЫ» нет в `EN`; кнопки карточек — это
  `RoundButton`, и после перерисовки каталога их текст возвращается к `_text` «Скачать», хотя
  подписи-`Label` и счётчик уже английские. В результате EN-каталог выглядит смешанным:
  «Cars», «duplicate · 2», «2165 mods», но «проверенные», «ФИЛЬТРЫ», «Скачать».
- **Как воспроизвести (9276/9279):** переключить язык в каталоге; `chips.verified` =
  «проверенные», `ФИЛЬТРЫ` не меняется, в текстах карточек — «Скачать» (по 24 карточки).
- **Ожидаемое поведение:** новые подписи переведены; кнопки карточек тоже.
- **Важность:** minor.

### 9. В EN-версии страницы мода остаются русские подписи «＋ В сборку» и плашка дубликата

- **Экран:** страница мода → English.
- **Что не так:** после перевода на странице остаются четыре кириллические строки: название
  похожего мода (это допустимо — имя мода), описание (контент, см. дефект 1), плашка
  «Такой же vесть ещё на: …» (искажённая, но русская) и кнопка «＋ В сборку». По заданию
  остаться должны только названия модов.
- **Как воспроизвести (9273/9277):** открыть `mg:161165`, English; `n_cyr_strings=4`,
  `cyr_unique` содержит «＋ В сборку» и «Такой же vесть ещё на: …».
- **Ожидаемое поведение:** «＋ В сборку» → «＋ Add to collection», плашка дубликата —
  по-английски.
- **Важность:** minor.

### 10. Профиль не показывает черновики: «Мои сборки 0 шт.», хотя в «Сборки → Мои» одна

- **Экран:** профиль → «Мои сборки»; сравнение с «Сборки → Мои».
- **Что не так:** `/api/user` (`app.py:693-695`) берёт `list_collections("mine")` и оставляет
  только `published`. Своя черновая сборка есть в «Сборки → Мои» (1), но в профиле
  «Сборки 0», «Мои сборки 0 шт.» и пустое состояние «Сборок пока нет».
- **Как воспроизвести (9274/9275):** создать сборку (она черновик), открыть профиль:
  в «Мои сборки» — 0 шт.; API `/api/user` → `collections_count=0`, `/api/collections?kind=mine`
  → 1 запись.
- **Ожидаемое поведение:** либо черновики видны в своём профиле, либо подпись/пустое состояние
  явно говорят, что показаны только опубликованные.
- **Важность:** minor.

## Что проверено и в порядке

1. **`/api/mods?verified=1`.** На двух базах (9270/9271) полная выдача по 120 записей сверена с
   SQL: `total=2135`, ровно те же id, ни одной записи без `image` или `description`
   (`missing_fields=0`, `only_db=0`, `only_api=0`). `verified=1&img=1` даёт те же 2135;
   `img=1` — 2139 (надмножество). `verified=` / `verified=yes` / `verified=2` — 200 и обычная
   выдача без 500.
2. **Счётчик «проверенных».** Каталог 2165 → 2135 после клика (реальный клик в 9278 и вызов
   обработчика в 9272/9276); повторный клик возвращает 2165.
3. **Метка RU.** Поиск «русск» даёт 4 мода; на всех четырёх карточках есть `RU`, ровно 4 метки
   (`ru_labels=4`, `expected_ru=4`). Метка 27×16 внутри строки 266×16, не обрезается; цвета
   `#20242f`/`#ffc08a`.
4. **Язык не закрывает страницу.** На 9273/9277 после `set_language("en")` и обратно
   `_page_active=true`, `page.winfo_ismapped()=true`, заголовок и число текстов сохраняются,
   новых `Toplevel` нет. Переключение дважды подряд тоже не закрывает страницу.
5. **Экраны без исключений (9274/9275).** Каталог, сборки (Популярные/Для вас/Новинки/Мои),
   форма «Новая сборка» (2 поля + описание/категория/теги/обложка), страница официальной и своей
   сборки, подбор мода («показано 60 из 2165», категории, «＋ Добавить»), отзывы, профиль,
   статистика, админка, отдельное окно «Модерация», библиотека/обновления/загрузки (пустые),
   настройки — без `report_callback_exception` (единственное исключение в прогонах — ошибка
   самого пробника из-за несуществующего `filter_chips["fav"]`, не приложения).
6. **Обсуждение.** Вошедшему видны комментарии и «Ответить»; поле ввода и «Отправить» на месте.
   Отправка из UI добавила «QA UI комментарий 0.13.9» (счётчик 1 → 2), «Ответить» подставил
   «Ответ на QB9275/QA9275». «Назад» вернул на страницу сборки с «＋ Добавить мод».
7. **Официальные сборки.** На первом `bootstrap()` все 8 сборок по 10 модов (9274/9275),
   без торрентов; «Драг» тоже 10 — дефект 0.13.5 № 4 закрыт.
8. **Disabled-кнопки, ссылка, настройки.** `RoundButton` в `disabled` после
   `<ButtonPress>/<ButtonRelease>` остаётся `disabled`, команда не вызывается. «＋ Ссылка» с
   `not-a-url` даёт «Ошибка: Нужна ссылка http(s)», а не «Добавлено». `auto_install` и
   `auto_check_updates`, сохранённые как `false`, после нового процесса остаются `false`
   (два temp-каталога).
9. **Статистика.** Лента «Активность / события за 14 дней» рисуется (столбик 1 за 11-19) —
   дефект 0.13.5 № 12 закрыт; топы модов/сборок и категории совпадают с `/api/stats`.

## Major

### 1. «Обсуждение» не рисуется вошедшему игроку: комментарии и «Ответить» видны только гостю

- **Экран:** страница сборки → «Отзывы и комментарии» → «Обсуждение».
- **Что не так:** блок комментариев оказался внутри `if not self.user:` (`core/tkui.py:3058-3111`).
  Внутри условия создаётся не только подпись «Войдите, чтобы писать» (`:3059-3060`), но и функция
  `comment_block` (`:3062`) и её вызов для каждого комментария (`:3110-3111`). Поэтому:
  - вошедший игрок видит заголовок «Обсуждение · N сообщений», поле ввода и «Отправить», но
    **ни одного комментария** и **ни одной кнопки «Ответить»**;
  - гость видит комментарии (условие ложно → блок выполняется), но у него нет `self.user`, поэтому
    «Ответить» не рисуется и ответить он не может;
  - отправить комментарий из интерфейса можно: `POST /api/comments` уходит и счётчик в шапке
    растёт, но свой же комментарий автор в списке не увидит.
- **Как воспроизвести (два прогона 9307/9308, разные temp-базы):** зарегистрировать двух игроков,
  создать сборку, добавить комментарий и ответ через API, открыть «Отзывы и комментарии» под
  автором: кнопки в дереве окна — `['Отмена', 'Отправить', 'Удалить оценку', 'Сохранить оценку',
  '★'×5]`, текста `QA комментарий 0.13.5` в подписях нет; под гостем та же страница показывает
  `QA комментарий 0.13.5` (и `QA ответ 0.13.5` в ответах). Дополнительно в 9280/9290: отправка
  из интерфейса увеличила `count` с 2 до 3, но текст в списке не появился.
- **Ожидаемое поведение:** комментарии и ответы видны всем; вошедшему есть «Ответить», гостю —
  «Войдите, чтобы писать».
- **Важность:** major — регрессия закрытия 0.13.3 № 6: поле и отправка появились, а отображение
  ветки сломано (правка 0.13.4). Это же ломает обещанные README «комментарии и ответы».

### 2. Настройки «автоустановка» и «автопроверка обновлений» нельзя выключить: после перезапуска снова включены

- **Экран:** Настройки → «Ставить новые архивы из «Загрузок» автоматически»; скрытый флаг
  `auto_check_updates`.
- **Что не так:** `config._migrate` (`core/config.py:167-169`) считает любой falsy-значение
  «пустым» и подставляет дефолт: `if default and not merged.get(key): merged[key] = default`.
  У `auto_install` и `auto_check_updates` дефолт `True` (`core/config.py:58,66`), поэтому
  сохранённый `false` при следующем `config.load()` превращается в `true`. В текущем сеансе
  чекбокс показывает выключенное состояние (кэш `_cached`), после перезапуска — снова включён,
  и BeamHub опять автоматически ставит всё, что появилось в «Загрузках». Дополнительно
  `App.__init__` (`core/tkui.py:182`) всегда планирует `check_updates()` через 5 с, вообще не
  глядя на `auto_check_updates`.
- **Как воспроизвести (два прогона, разные temp-каталоги):** процесс 1 —
  `config.save(dict(DEFAULTS, auto_install=False, auto_check_updates=False))`, в файле оба `false`;
  процесс 2 — `config.load()` → `auto_install=True`, `auto_check_updates=True`. В окне это видно
  косвенно: в прогоне 9307 архив `QA Архив.zip`, положенный в «Загрузки» до старта, был установлен
  вотчером (`[beamhub] installed: Установлено: QA Архив`) несмотря на `auto_install: false` в
  settings.json; пользователь не нажимал ни «Установить», ни «Установить все».
- **Ожидаемое поведение:** выключенный чекбокс сохраняется и после перезапуска; автоустановка не
  срабатывает.
- **Важность:** major — настройка молча игнорируется, действие выполняется против выбора игрока.

## Minor

### 3. Клик по отключённой кнопке включает её обратно (№ 12 закрыт частично)

- **Экран:** каталог (стрелки `‹`/`›` на границах), «Загрузки» (неактивная «Установить» у
  невалидного архива), «Всё установлено» и другие disabled-кнопки.
- **Что не так:** `RoundButton._on_release` (`core/theme.py:381-384`) безусловно ставит
  `self._state = "normal"` и перерисовывает кнопку, даже если она была `disabled`. В итоге:
  - на первой странице каталога `‹` изначально `disabled`, но после одного клика становится
    `normal` (подсветка и `hand2` возвращаются), хотя действие всё ещё `None`;
  - на последней странице то же с `›`;
  - у мусорного архива в «Загрузках» кнопка «Установить» изначально `disabled`, после клика —
    `normal`; второй клик уже вызывает `install_file` (сервер отвечает «не похоже на мод»).
- **Как воспроизвести (9307/9308 — обе границы; 9340/9341 — повтор; 9280 — первый прогон):**
  у `‹` на стр. 1 `state=disabled`, после `<ButtonPress>/<ButtonRelease>` — `state=normal`;
  у `›` на последней странице (стр. 91) то же; у невалидного архива `state=disabled` → клик →
  `normal`. Ни один клик не должен менять состояние.
- **Ожидаемое поведение:** disabled-кнопка остаётся disabled и не реагирует на клики.
- **Важность:** minor. Исходная жалоба № 12 («выглядят активными на границах») закрыта: теперь они
  действительно `disabled` при отрисовке; но один клик возвращает активный вид.

### 4. Официальная сборка «Драг: базовый набор» на первом запуске — 8 модов, а не 10

- **Экран:** «Сборки» → официальные подборки BeamHub Team.
- **Что не так:** `official.ensure()` сначала вызывает `refill()` (добивает существующие сборки до
  10), и только потом создаёт отсутствующие (`core/official.py:60-89`). Новая сборка получает
  ровно столько модов, сколько нашлось по ключевым словам (`_pick_mods`, лимит 10). Для «Драга»
  ключевые слова дают 8 совпадений, поэтому на чистой базе в сборке 8 модов; при следующем
  запуске `refill()` добирает до 10.
- **Как воспроизвести (9270/9271/9272 + отдельный прогон):** на свежей копии `seed` после
  `bootstrap()` в `/api/collection` у «Драг: базовый набор» 8 позиций, у остальных 7 сборок — 10;
  второй `bootstrap()` на той же базе — 10. Официальные сборки есть (8), торрентов нет
  (`source='playground'` — 0), у остальных по 10.
- **Ожидаемое поведение:** уже на первом запуске в каждой официальной сборке 10 модов.
- **Важность:** minor (контент; лечится перезапуском, но игрок видит неполную подборку).

### 5. «＋ Ссылка» при ошибке пишет «Добавлено: мод»

- **Экран:** шапка → «＋ Ссылка».
- **Что не так:** `on_add_link` (`core/tkui.py:4484-4501`) не проверяет `ok` ответа: при
  `POST /api/add-link` с не-http строкой сервер отвечает `400` и `{"ok": false, "error": "Нужна
  ссылка http(s)"}`, а интерфейс берёт `data.get("item", {}).get("title", "мод")` → «мод», ставит
  статус «Добавлено: мод» и перерисовывает каталог. Мод, разумеется, не добавлен.
- **Как воспроизвести (9310/9311):** `simpledialog.askstring` возвращает `abc`; после клика
  статус — `Добавлено: мод`, каталог перерисован, в базе мода нет. Сервер в это время вернул 400.
- **Ожидаемое поведение:** «Ошибка: нужна ссылка http(s)», каталог не перерисовывается.
- **Важность:** minor (ложный успех).

### 6. «Назад» из «Отзывов и комментариев» ведёт не на страницу сборки

- **Экран:** страница сборки → «Отзывы и комментарии» → «← Назад».
- **Что не так:** `collection_reviews` открывает страницу без `back` (`core/tkui.py:2875-2876`),
  поэтому `_page_back` остаётся прежним (`None` при открытии сборки из каталога/списка), и
  `_hide_page` вызывает `switch(self.view)` — каталог или список сборок. Страница сборки теряется.
- **Как воспроизвести (9310/9311):** сборка → «Отзывы и комментарии» → «← Назад»:
  `page=False`, `title=Каталог модов`, `view=catalog`; если открывать из «Сборок» — вернёт список
  сборок, а не сборку.
- **Ожидаемое поведение:** «Назад» возвращает на страницу сборки, откуда открыли отзывы.
- **Важность:** minor (навигация; аналогично закрытому № 18).

### 7. Английская версия страницы мода переведена частично

- **Экран:** страница мода (и блок совместимости/похожих) при языке EN.
- **Что не так:** в `i18n.EN` нет ключей для части подписей, а фразы переводятся по шаблонам,
  из-за чего получается смесь: «Version мода», «Version игры», «Добавлен», «Скачиваний»,
  «Размер», «Конфликты», «заявлено «0.40.x», installed «не определено»», «с установленными модами
  не найдено», «Машины · 400.43 MB». На странице сборки так же остаются «Действия», «Установка»,
  «Состав».
- **Как воспроизвести (9308 и 9310):** переключить язык на EN, открыть мод: видимые подписи
  содержат кириллицу (`EN mod page cyrillic=[...]`), в том числе «Version мода»; `i18n.EN` не
  содержит ключей «Версия мода», «Версия игры», «Добавлен», «Скачиваний», «Размер».
- **Ожидаемое поведение:** на EN-странице мода нет русских подписей; «Версия мода» → «Mod
  version», «Добавлен» → «Added» и т. д.
- **Важность:** minor (локализация; раньше проверялись только настройки).

### 8. Переключение языка закрывает открытую страницу мода/сборки

- **Экран:** любая внутренняя страница (мод, сборка, отзывы), кнопка RU/EN в шапке.
- **Что не так:** `set_language` (`core/tkui.py:695-702`) вызывает `refresh_all()`, а тот —
  `switch(self.view)` (`:655-658`); `switch` при `_page_active` вызывает `_close_page_silent()`
  (`:797-799`). Открытая страница закрывается без предупреждения, игрок оказывается в каталоге
  (или в списке текущей вкладки).
- **Как воспроизвести (9307/9308, 9310):** открыть мод, нажать EN: `after lang toggle:
  page=False view=catalog title=Mod catalog`. То же при RU.
- **Ожидаемое поведение:** страница остаётся открытой и переводится (или хотя бы сохраняется
  возможность вернуться).
- **Важность:** minor (потеря контекста при смене языка).

### 9. «Проверить ещё раз» на пустых «Обновлениях» проверяет версию BeamHub, а не моды

- **Экран:** «Обновления» → пустое состояние «Всё актуально» → «Проверить ещё раз».
- **Что не так:** текст пустого состояния говорит про моды, но действие —
  `self.check_updates(silent=False)` (`core/tkui.py:4435-4441`), а `check_updates` — это
  автообновление самого приложения через GitHub Releases (`:4216-4254`). В результате на экране
  «Обновления модов» появляется «Установлена последняя версия 0.13.5» и диалог «Обновления» —
  про лаунчер, а не про моды.
- **Как воспроизвести (9307/9308):** удалить все установленные строки, открыть «Обновления»
  (пусто, «Всё актуально»), нажать «Проверить ещё раз»: статус и `showinfo` —
  «Установлена последняя версия 0.13.5», при том что проверка модов не запускалась.
- **Ожидаемое поведение:** кнопка пересканирует библиотеку/каталог и сообщает про обновления
  модов; либо её нет.
- **Важность:** minor (кнопка делает не то, что обещает).

### 10. `py app.py --diagnose` падает с `NameError` и вешает процесс

- **Экран:** CLI (`--diagnose`).
- **Что не так:** в ветке диагностики используется несуществующая переменная `desktop`
  (`app.py:1590-1592`; в модуле есть `appwindow`, `launcher_ui`, `tkui`, но не `desktop`).
  Исключение ловится верхним обработчиком `__main__`, который вызывает `show_error` с
  `MessageBoxW` — в консольном/автоматическом запуске окно висит до нажатия кнопки.
- **Как воспроизвести (2 прогона через обёртку, подменяющую `show_error`):**
  `NameError: name 'desktop' is not defined`, `--diagnose` не печатает результаты. В реальном
  запуске без подмены `MessageBoxW` блокирует процесс (в 0.10.0 это уже было дефектом № 15).
- **Ожидаемое поведение:** диагностика печатает состояние окна/движка и завершается.
- **Важность:** minor (служебная команда; повтор старого дефекта 0.10.0 № 15).

### 11. `_clean_seed` не чистит `rate_limits`, `stats_events`, `admin_actions`, `collection_versions`

- **Экран:** сборка exe (`build_exe.py` → `prepare_seed`).
- **Что не так:** список таблиц в `_clean_seed` (`build_exe.py:36-38`) включает `users`,
  `sessions`, `collections`, `collection_items`, `comments`, `ratings`, `reports`, `follows`,
  `favorites`, `installed`, `meta`, но не трогает:
  - `rate_limits.key` — там ключи вида `comment:usr_…`, `rate:usr_…` (идентификатор аккаунта);
  - `stats_events.user_id`, `stats_events.collection_id`;
  - `admin_actions.actor_id` и `note` (личные заметки модератора);
  - `collection_versions` (снимки чужих сборок, `note`).
  Закоммиченный `seed/beamhub.db` сейчас чист (все эти таблицы пусты), поэтому дефект № 17 для
  поставляемой базы закрыт. Но сборка из рабочей `data/beamhub.db` с историей действий пронесёт
  эти строки в комплект — это персональные данные.
- **Как воспроизвести (2 прогона):** в копию seed вставить строки `rate_limits('comment:usr_secret')`,
  `stats_events(user_id='usr_secret')`, `admin_actions(actor_id='usr_secret')`,
  `collection_versions(note='черновик')`, вызвать `build_exe._clean_seed` — все четыре строки
  остаются.
- **Ожидаемое поведение:** перечисленные таблицы тоже очищаются (или чистка идёт по списку всех
  таблиц, кроме `mods`/`mod_stats`).
- **Важность:** minor (риск утечки идентификаторов при сборке из рабочей базы; сам seed чист).

### 12. «Статистика сообщества»: нет ленты активности за 14 дней

- **Экран:** Настройки → «Статистика сообщества».
- **Что не так:** `/api/stats` отдаёт `activity` (лента событий по дням), README обещает «ленту
  активности за 14 дней», но `stats_window` (`core/tkui.py:1852-1940`) рисует только «Сводку»,
  «Топ модов», «Топ сборок» и «Категории». Блок активности отсутствует.
- **Как воспроизвести (9330/9331):** гость дважды открывает сборку (создаются `view`-события),
  `/api/stats` → `activity=[{'day': '2026-11-19', 'kind': 'view', 'events': 2}]`; на странице
  статистики подписей «Активность»/«за 14 дней» нет.
- **Ожидаемое поведение:** лента активности (14 дней) отрисована или README не обещает её.
- **Важность:** minor (обещание в README не выполнено).

### 13. Поля путей в настройках без проверки

- **Экран:** Настройки → «Папка модов игры», «Папка загрузок», «GitHub-репозиторий обновлений».
- **Что не так:** `save_settings` (`core/tkui.py:4199-4206`) отправляет значения как есть, API
  `config.update` их принимает, статус — «Настройки сохранены». Несуществующий путь
  `Z:\нет-такого-пути` сохраняется без предупреждения (проверка появится только при попытке
  установки), пустой/кривой репозиторий — тоже.
- **Как воспроизвести (9330/9331):** вписать в «Папку модов игры» `Z:\нет-такого-пути`, нажать
  «Сохранить»: статус «Настройки сохранены», `config.load()['mods_dir']` = этот путь; ошибки нет.
- **Ожидаемое поведение:** предупреждение/проверка существования папки и формата `owner/repo`
  (или сообщение, что путь будет создан).
- **Важность:** minor (поле без валидации).

4. Каждый дефект ниже подтверждён двумя независимыми прогонами: для интерфейса — два полных

## Major

### 1. «＋ В сборку» на странице мода падает с `AttributeError`: метода нет

- **Экран:** страница мода (открывается из каталога, из сборки, из «Похожих модов»).
- **Что не так:** кнопка вызывает `self.pick_collection_for_mod(item)` (`core/tkui.py:1328`),
  а такого метода у `App` нет — есть только старый `add_to_collection_from_catalog`
  (`core/tkui.py:3112`), который сейчас никто не вызывает (мёртвый код). Клик уходит в
  `report_callback_exception`: `AttributeError: 'App' object has no attribute
  'pick_collection_for_mod'`. Внешне не происходит ничего — ни диалога, ни тоста, ни строки
  статуса.
- **Как воспроизвести:** каталог → клик по карточке → «＋ В сборку». В обоих прогонах окна
  (`9260`/`9261`) счётчик исключений Tk увеличивался ровно на 1 с этим текстом; страница не
  менялась.
- **Ожидаемое поведение:** открывается выбор своей сборки (как в 0.12.13 — инлайн-панель
  `add_to_collection_from_catalog`), мод добавляется; либо кнопки нет.
- **Важность:** major (регрессия: в 0.12.13 кнопка работала).

### 2. «Установить все (N)» в «Загрузках» падает с `NameError`

- **Экран:** Загрузки, кнопка «Установить все (2)».
- **Что не так:** `install_all` (`core/tkui.py:3223-3239`) первым делом зовёт
  `human_size(total_size)` (`core/tkui.py:3224`), но `human_size` в `tkui.py` не импортирован
  (из `core.util` берутся только `CATEGORY_LABELS`, `CATEGORY_ORDER`, `human_ago`, `human_date`,
  `title_key`, строки 30-32). Проброс в Tk:
  `NameError: name 'human_size' is not defined. Did you mean: 'human_date'?` Установка не
  начинается, подтверждения нет.
- **Как воспроизвести:** «Загрузки» → «Установить все (2)» → 7 с ожидания: исключение Tk в
  обоих прогонах, число архивов в списке и в папке модов не меняется, сообщений нет.
  Для сравнения: тот же путь через API (`POST /api/inbox/install-all`) работает —
  «Готово: установлено 2, пропущено 0, ошибок 0».
- **Ожидаемое поведение:** вопрос «Установить N архивов?» и установка (API это умеет).
- **Важность:** major.

### 3. «Сменить фото» не сохраняет аватар (ложное «Фото обновлено»)

- **Экран:** Профиль → «Сменить фото».
- **Что не так:** файл выбирается, режется до 128×128 и кладётся в `data/avatars/<id>.png`
  (`core/tkui.py:1754-1777`), затем уходит `POST /api/profile {"avatar_url": ...}`
  (`core/tkui.py:1772`). Обработчик `/api/profile` (`app.py:896-897`) пропускает только
  `nickname`, `bio`, `avatar_color` — `avatar_url` молча выбрасывается, хотя
  `accounts.update_profile` его поддерживает (`core/accounts.py:158`). Ответ `ok: true`, тост
  «Фото обновлено», а аватар не появляется.
- **Как воспроизвести:** Профиль → «Сменить фото» → выбрать PNG. Замеры в двух прогонах:
  тост `ok «Фото обновлено»`, файл `data/avatars/usr_*.png` создан, но `GET /api/auth/me` →
  `avatar_url: ""`, при перерисовке профиля в аватаре по-прежнему буква «Q» без картинки.
  То же на HTTP-уровне: `POST /api/profile {"avatar_url": "avatars/qa.png"}` → в ответе и в
  `/api/auth/me` пустая строка (два прогона: 9250/9251).
- **Ожидаемое поведение:** `avatar_url` сохраняется, после перерисовки в профиле картинка.
- **Важность:** major.

### 4. Первый зарегистрированный пользователь не получает админку

- **Экран:** регистрация → «Настройки»/меню аккаунта (кнопки «Админ-панель» и «Модерация»).
- **Что не так:** `_maybe_first_admin` (`core/accounts.py:56-61`) выдаёт роль только если в базе
  ровно один пользователь и нет ни одного админа. Но `official.ensure()` при каждом старте
  (`app.py:1521-1524`) создаёт служебного «BeamHub Team» с `role=admin`
  (`core/official.py:38-43`), а в поставляемом `seed/beamhub.db` лежит ещё и тестовый
  `beamhub-rev-594a` (тоже admin). Итог: `total` ≥ 2 и `admins` ≥ 1 — новому пользователю роль
  не достаётся никогда, а войти в служебные аккаунты нельзя (`provider` не `local`).
- **Как воспроизвести:** свежая копия seed → `py app.py --no-browser` → регистрация через
  `/api/auth/register` (ник «QA Audit»). В двух HTTP-прогонах: `role: "user"`, `GET
  /api/admin/stats` → 403 «Нужны права администратора». В окне: у «QA Audit» в меню и настройках
  кнопок «Админ-панель»/«Модерация» нет; после выдачи роли вручную админка открывается и её
  11 цифр совпадают с `/api/admin/stats`. В seed-базе: `users` = 1 запись
  `beamhub-rev-594a@example.com`, `role=admin`, и черновик «Сборка для отзывов».
- **Ожидаемое поведение:** первый живой аккаунт на чистой базе — админ (как обещает 0.12.5 и
  как проверено в 0.12.13), админ-панель достижима.
- **Важность:** major (регрессия с 0.12.15: раньше первый пользователь становился админом).

### 5. Счётчик в шапке и строка статуса залипают на старом тексте

- **Экран:** все вкладки, шапка (`count_label`) и нижняя строка статуса.
- **Что не так:** `render_collections` запоминает `count_label._ru_text = "N сборок"`
  (`core/tkui.py:2017-2021`), а `_translate_ui` в русском режиме возвращает запомненный текст
  любому `Label`, у которого текущий текст отличается от `_ru_text`
  (`core/tkui.py:694-697`). Тик `_lang_tick` повторяет это каждые 2.5 с (`core/tkui.py:637-643`).
  Поэтому после посещения «Сборок» счётчик на всех остальных вкладках откатывается к «N сборок»,
  а после переключения языка EN→RU так же замораживается строка статуса.
- **Как воспроизвести (два прогона, `9260`/`9261`):**
  - каталог после «Сборок»: `reload()` ставит «2165 модов», через 3.2 с в шапке снова
    «9 сборок»; поиск «bmw» (`total` 140) — счётчик «9 сборок»; категория «Карты» (320) —
    «9 сборок»;
  - «Библиотека», «Загрузки», «Обновления», «Настройки» — во всех случаях «9 сборок» вместо
    «2 файлов», «3 архивов · к установке 2», «1 обновлений», пустого счётчика;
  - `set_status("QA проверка статуса")` → через 3.2 с в строке статуса снова «Настройки сохранены»;
    то же с сообщением «Открыл страницу мода в браузере…» после «Скачать».
- **Ожидаемое поведение:** счётчик и статус показывают актуальный текст текущего экрана/действия.
- **Важность:** major (не исправленный дефект 0.12.13 № 3, теперь задевает и каталог, и статус).

### 6. В «Отзывах и комментариях» нельзя оставить комментарий или ответ

- **Экран:** «Отзывы и комментарии» (страница сборки).
- **Что не так:** страница рисует оценки, поле отзыва и раздел «Обсуждение»
  (`core/tkui.py:2423-2481`), но поля ввода комментария и кнопок «Отправить»/«Ответить» нет —
  есть только «Удалить» у своих комментариев. При этом API умеет добавлять, править и удалять
  комментарии (`app.py:1030-1042`, `/api/comments`).
- **Как воспроизвести:** страница сборки → «Отзывы и комментарии». В двух прогонах в дереве окна
  ровно один `Text` (поле отзыва), кнопки — «← Назад», 5 звёзд, «Сохранить оценку»,
  «Удалить оценку»; ни одного элемента с «коммент»/«ответ». `POST /api/comments` из пробы → 200
  `ok: true`, то есть данные создать можно, а из интерфейса — нет.
- **Ожидаемое поведение:** в «Обсуждении» есть поле и кнопка отправки (и ответ на комментарий),
  иначе раздел не нужен.
- **Важность:** major (не исправленный дефект 0.10.0 № 1).

### 13. Кривые числовые query-параметры → 500 с текстом исключения

- **Экран:** локальный API (в интерфейсе таких запросов нет, но это 500 на ровном месте).
- **Что не так:** `int(...)` без проверки: `app.py:393-394` (`/api/mods`), `478`

  → `500 «Недопустимый адрес картинки»` вместо 400.
- **Как воспроизвести:** `GET /api/mods?limit=abc`, `?offset=xyz`, `/api/events?since=abc`,
  `/api/recommend/mods?limit=abc`, `/api/collections?limit=abc`, `/api/img?u=not-a-url`.
  Все шесть — 500 в двух прогонах (9250/9251).
- **Ожидаемое поведение:** 400 с коротким «Неверный параметр» (или значение по умолчанию).
- **Важность:** minor (не исправленный дефект 0.10.0 № 14).

### 14. «Автоустановка»: при неудаче нет причины ошибки

- **Экран:** страница сборки, строка статуса и тосты.
- **Что не так:** воркер `POST /api/collections/install` (`app.py:1163-1207`) на ошибке шлёт

  `download_and_install` теряется; итог — «установлено 0, не удалось 2».
- **Как воспроизвести:** сборка из 3 модов с недоступными ссылками → «Автоустановка»:
  три тоста «Не удалось: <мод>», итог «Сборка: установлено 0, не удалось 3». Причина (таймаут,
  403, нехватка места) не показывается нигде. Два прогона — одинаково.
- **Ожидаемое поведение:** в событии/строке статуса — короткая причина (`result["error"]`).
- **Важность:** minor.

### 15. Скачанный «Автоустановкой» архив остаётся в `data/tmp`

- **Экран:** «Автоустановка» (успешный сценарий).
- **Что не так:** `download_and_install` (`app.py:1433-1470`) кладёт загрузку в
  `DATA_DIR/tmp/<название>.zip` и никогда её не удаляет; `install_archive` работает с копией.
- **Как воспроизвести:** мод со ссылкой на локальный HTTP-сервер → «Автоустановка»: событие
  «Установлено: QA Мод по ссылке», файл в папке модов есть, и `data/tmp/QA Мод по ссылке.zip`
  остаётся. При повторных установках папка растёт.
- **Ожидаемое поведение:** временный архив удаляется после установки.
- **Важность:** minor.

### 16. «Сопоставить с каталогом»: статус висит «Сопоставляю…»

- **Экран:** Библиотека.
- **Что не так:** `match_library` (`core/tkui.py:1565-1577`) ставит статус перед работой и не
  обновляет его после; результат показывается только модальным окном.
- **Как воспроизвести:** «Библиотека» → «Сопоставить с каталогом» → в окне «Сопоставлено: 0 из 1»,
  а в строке статуса остаётся «Сопоставляю моды с каталогом…» (в двух прогонах; после этого
  статус ещё и залипает из-за дефекта № 5).
- **Ожидаемое поведение:** «Сопоставлено: 0 из 1» в строке статуса.
- **Важность:** minor.

### 17. `_clean_seed` не чистит аккаунты и сборки — в комплект едет чужой админ

- **Экран:** сборка exe (комплект `seed/beamhub.db`).
- **Что не так:** `_clean_seed` (`build_exe.py:30-44`) удаляет только `installed`, `favorites`
  и `meta`. Таблицы `users`, `sessions`, `collections`, `collection_items`, `comments`,
  `ratings`, `reports` остаются. В закоммиченном `seed/beamhub.db` уже лежит
  `beamhub-rev-594a@example.com` (`role=admin`, `provider=email`) и черновик «Сборка для отзывов»;
  при сборке из рабочей `data/beamhub.db` туда попадут и реальные аккаунты разработчика.
- **Как воспроизвести:** `sqlite3 seed/beamhub.db "select email,nickname,role,provider from users"`
  → одна запись `beamhub-rev-594a`, admin; `select title,published from collections` → «Сборка для
  отзывов», 0. После копии seed в temp и старта: `users` = 2 (тестовая + «BeamHub Team»),
  `collections` = 9, первый зарегистрированный — `user` (см. дефект № 4).
- **Ожидаемое поведение:** в комплекте только каталог модов; пользователи, сессии, сборки,
  отзывы и жалобы вычищаются.
- **Важность:** minor (но вместе с № 4 закрывает доступ к админке).

### 18. «Мод → Похожие моды → Назад» возвращает не в предыдущий мод

- **Экран:** страница мода, блок «Похожие моды».
- **Что не так:** клик по похожему моду работает (`details_by_id`, `core/tkui.py:1403-1412`), но
  `details(...)` вызывается без `back`, поэтому в `_page_back` остаётся прежний переход: из
  каталога — каталог, из сборки — страница сборки. Сам мод, откуда пришли, теряется.
- **Как воспроизвести:** каталог → мод «Ibishu CrossSport…» → клик по «Lada Vesta Sport…» →
  «← Назад»: `_page_active=false`, `view=catalog`, подпись под закрытой страницей — «Lada Vesta
  Sport», то есть вернулись в каталог, а не к «Ibishu». Из сборки «Назад» ведёт на страницу
  сборки, минуя мод. Два прогона — одинаково.
- **Ожидаемое поведение:** «Назад» возвращает на страницу мода, с которой открыли похожий.
- **Важность:** minor.

## Major

### 1. Каталог не пересчитывает колонки при изменении размера окна — карточки уходят за правый край

- **Экран:** Каталог.
- **Что не так:** `_scrollable_frame` (`core/tkui.py:694`) вешает `<Configure>` на `self.canvas`
  без `add="+"` и перетирает обработчик `_on_resize`, повешенный в `_build` (`core/tkui.py:285`),
  а заодно и `sync_scroll` (`core/tkui.py:693`). В результате `_apply_resize` по ресайзу не
  вызывается, `_columns` застревает, а `_grid_columns()` считает уже другое число колонок.
  Проверено напрямую: `canvas.bind("<Configure>")` содержит только лямбду установки ширины,
  вызова `_on_resize` в привязке нет.
- **Как воспроизвести:** развернуть окно на весь экран (2560×1440, canvas 2290 px, 7 колонок) →
  «Показать ещё» (48 карточек) → вернуть окно в 1200×760. Canvas становится 930 px,
  `_columns` = 7, `_grid_columns()` = 3. Правый край последней карточки `winfo_x + winfo_width`
  = 2065 px, то есть на **1135 px правее canvas**; через 1.8 с и в повторном прогоне — те же
  7 колонок и те же 1135 px. Карточки обрезаны, горизонтальной прокрутки нет.
- **Ожидаемое поведение:** при сужении окна сетка пересчитывается (3 колонки на 930 px), карточки
  остаются внутри canvas; при расширении — наоборот, колонок больше.
- **Важность:** major. Оговорка: на широком окне сразу после старта переполнения нет
  (правый край 2065 при canvas 2290, запас −225 px) — пункт жалобы «не выходят за правый край»
  на самом широком окне выполняется, но ломается при обычном сужении/восстановлении окна.

## Minor

### 2. Полотно каталога не растягивается на всю ширину — пустая полоса 218 px справа

- **Экран:** Каталог (сразу после старта/перерисовки на широком окне).
- **Что не так:** ширина окна-полотна выставляется только внутри обработчика `<Configure>`

  при этом левый отступ 7 px (асимметрия).
- **Как воспроизвести:** запустить окно на весь экран, дождаться каталога (или нажать «Показать
  ещё») — карточки занимают 2072 px, правее пустая полоса; в двух прогонах числа совпали.
- **Ожидаемое поведение:** полотно каталога занимает всю ширину canvas (2290 px), карточки
  распределяются по ней.
- **Важность:** minor.

### 3. Счётчик раздела залипает на «1 сборок» на других вкладках

- **Что не так:** `render_collections` запоминает `count_label._ru_text = "1 сборок"`

- **Как воспроизвести:** открыть «Сборки» (1 сборка) → «Каталог» → подождать 3 с: в шапке

  В обоих прогонах: `catalog_after_tick="1 сборок"`, `library_ru_text="1 сборок"`.
- **Ожидаемое поведение:** счётчик соответствует открытому разделу.
- **Важность:** minor.

### 4. Стрелки «‹»/«›» на границах страниц выглядят активными, но не работают

- **Как воспроизвести:** каталог, страница 1 → нажать «‹» (ничего) и сравнить со страницей 2.

- **Ожидаемое поведение:** на первой/последней странице стрелка визуально неактивна (или скрыта).
- **Важность:** minor.

### 5. После «Показать ещё» счётчик остаётся «стр. 1», хотя страница уже 2

- **Экран:** Каталог.
- **Что не так:** `load_more` (`core/tkui.py:847-866`) обновляет `page_no`, но не

- **Ожидаемое поведение:** счётчик показывает «стр. 2» (или не показывает страницу вовсе).
- **Важность:** minor.

### 6. Заголовок сборки дублируется дважды

- **Важность:** minor.

## Major

### 1. Экран «Отзывы»: нельзя оставить комментарий, ответить или изменить его

- **Экран:** Сборки → сборка → «Отзывы».
- **Что не так:** под «Обсуждением» показываются комментарии и кнопки «Удалить», но нет поля
  ввода, кнопки «Отправить», «Ответить» и «Изменить». Комментарии из приложения создать нельзя —
  только через API. Это регрессия 0.10.0: в предыдущих версиях форма была (`reviews.png`), коммит
  `6b22b6e` при переносе экрана внутрь окна удалил `send_comment`, `reply_box`, `edit_comment`
  и пометку «изменён».
- **Как воспроизвести:** открыть сборку «Дрифт по-русски» → «Отзывы (2)» → прокрутить вниз до
  «Обсуждения»: поля ввода и кнопок «Отправить»/«Ответить»/«Изменить» нет. В пробе:
  `has_send=false, has_reply=false, has_edit=false`, на всей странице один `Text` — поле отзыва.
- **Ожидаемое поведение:** под обсуждением — поле ввода и «Отправить»; у своего комментария —
  «Изменить», у любого — «Ответить». API (`POST /api/comments`, `/api/comments/update`) при этом
  работает: проверено, комментарий/ответ/правка проходят.
- **Важность:** major.

### 2. Колесо мыши не прокручивает страницы — крутится скрытый каталог

- **Экран:** страница мода, страница сборки, отзывы, «Добавить мод в сборку».
- **Что не так:** `_on_wheel` (`core/tkui.py:658`) прокручивает только `self.canvas` (каталог),
  а страницы живут в отдельном `self._page_canvas` (`core/tkui.py:615-641`), на который
  `<MouseWheel>` не повешен. Пока страница открыта, каталог скрыт, поэтому колесо не делает
  ничего видимого, зато меняет `yview` скрытого каталога.
- **Как воспроизвести:** открыть мод с длинным описанием (контент 897 px при окне 679 px) или
  «＋ Добавить мод» (1748 px) и покрутить колесо: `page_yview` не меняется
  (`[0.0, 0.757]` → `[0.0, 0.757]`), а у скрытого каталога `[0.039, 0.433]` → `[0.078, 0.472]`.
  Прокрутить можно только полосой прокрутки.
- **Ожидаемое поведение:** колесо прокручивает видимую страницу; на страницах каталога — каталог.
- **Важность:** major.

### 3. «＋ В сборку» на странице мода не даёт видимой реакции

- **Экран:** страница мода.
- **Что не так:** `add_to_collection_from_catalog` (`core/tkui.py:2528-2565`) вставляет панель
  «Добавить «…» в сборку:» в `self._cards_frame` — фрейм каталога, который скрыт, пока открыта
  страница (`_show_page`). Кнопка выглядит «мёртвой»: пользователь нажимает и ничего не видит.
- **Как воспроизвести:** каталог → клик по карточке → на странице мода «＋ В сборку». Снимок
  до и после совпадает; панель создаётся (`bar_created=true`), но её родитель скрыт
  (`catalog_canvas_visible=false`). Панель появляется только после «Назад» — уже на каталоге.
- **Ожидаемое поведение:** панель выбора сборки видна сразу (на странице мода или в диалоге),
  либо кнопка открывает полноценный выбор сборки.
- **Важность:** major.

### 4. Переключение языка ломает подписи: заголовок «залипает», кнопки мигают

- **Экран:** любая навигация после смены языка; настройки → English → Русский.
- **Что не так:** `_translate_ui` (`core/tkui.py:505-585`) запоминает `_ru_text` у каждого
  виджета и при возврате на русский восстанавливает его, даже если текст с тех пор поменялся
  (заголовок раздела, счётчик). Поэтому после пары переключений шапка перестаёт обновляться.
  Отдельно кнопки-«скругления» (`theme.RoundButton`) при перерисовке берут `self._text`
  (русский) и `_lang_tick` возвращает перевод только через ≤2.5 с — текст мигает.
- **Как воспроизвести:**
  1. Окно на русском → Настройки → English → навести курсор на кнопку «Download» (каталог):
     видимый текст становится «Скачать»; через ≤2.5 с снова «Download».
     Замер: `en_button_visible="Download"` → `after_hover_visible="Скачать"` → `after_tick="Download"`.
  2. English → Русский → перейти в «Настройки», затем в «Каталог»: заголовок в шапке остаётся
     «Каталог модов» (в другом прогоне застрял на «Настройки»), т.е. не соответствует разделу;
     счётчик раздела тоже может остаться старым. Замер: `title_settings="Каталог модов"`.
- **Ожидаемое поведение:** после смены языка все подписи соответствуют текущему разделу и языку;
  наведение мыши не меняет язык кнопки.
- **Важность:** major.

## Minor

### 5. Дублирующийся заголовок на странице мода и странице сборки

- **Экран:** страница мода, страница сборки.
- **Что не так:** `_show_page` рисует шапку «← Назад + название» (`core/tkui.py:615-627`),
  а контент рисует этот же заголовок ещё раз (`core/tkui.py:931`, `1772`).
- **Как воспроизвести:** открыть сборку — «Дрифт по-русски» дважды подряд; открыть мод —
  «BMW E34 Drift Edition» дважды. См. `qa/tkui-collection-page.png`, `qa/tkui-mod-page.png`.
- **Ожидаемое поведение:** один заголовок (в шапке — «Назад» + название, в контенте — без повтора).
- **Важность:** minor.

### 6. «Отзывы (N)» считает комментарии, а не отзывы

- **Экран:** страница сборки.
- **Что не так:** в кнопке `f"Отзывы ({coll['comments_count']})"` (`core/tkui.py:1802`) стоит
  число комментариев, а сам экран показывает и отзывы, и комментарии.
- **Как воспроизвести:** сборка «JDM классика» — 1 отзыв с текстом, 0 комментариев → кнопка
  «Отзывы (0)».
- **Ожидаемое поведение:** согласованный счётчик (например «Отзывы и комментарии (3)») или
  отдельные счётчики.
- **Важность:** minor.

### 7. Миниатюры в «Добавить мод в сборку» сжаты до 16×8

- **Экран:** страница «Добавить мод в сборку».
- **Что не так:** `tk.Label(row, width=12, height=4)` получает картинку 232×130
  (`core/tkui.py:2477-2480`) и обрезается до 16×8. Вместо превью — узкая полоска.
- **Как воспроизвести:** сборка → «＋ Добавить мод»: у строк картинка `image 232×130`,
  виджет `16×8`. См. `qa/tkui-add-mod-thumbs.png`.
- **Ожидаемое поведение:** превью ~96×54 (как обложки сборок) без обрезки.
- **Важность:** minor.

### 8. Картинка на странице мода не масштабируется

- **Экран:** страница мода.
- **Что не так:** контейнер высотой 240 px на всю ширину, картинка ресайзится до 232×130
  (`core/tkui.py:924-930`) и висит по центру чёрной полосы: поля ~427 px с каждой стороны.
- **Как воспроизвести:** открыть мод с картинкой: виджет `1086×240`, картинка `232×130`.
  См. `qa/tkui-mod-page.png`.
- **Ожидаемое поведение:** картинка по ширине страницы (с сохранением пропорций) либо полоса
  высотой по картинке.
- **Важность:** minor.

### 9. «Назад» из подборщика мода теряет страницу сборки

- **Экран:** «Добавить мод в сборку».
- **Что не так:** `_hide_page` (`core/tkui.py:643-646`) просто прячет страницу и показывает
  каталог/список сборок; стек страниц не ведётся.
- **Как воспроизвести:** сборка → «＋ Добавить мод» → «← Назад»: оказываемся в списке сборок,
  а не на странице сборки, откуда пришли.
- **Ожидаемое поведение:** возврат на предыдущую страницу (страницу сборки).
- **Важность:** minor.

### 10. Категории в подборщике мода не соответствуют каталогу

- **Экран:** «Добавить мод в сборку».
- **Что не так:** чипы берутся из `MOD_PICK_CATEGORIES = ("cars","maps","skins","configs","mods","other")`
  (`core/tkui.py:2419`), а в каталоге категории `cars/maps/tools/planes/bikes/boats/other`
  (`core/util.py:39-49`). «skins», «configs», «mods» всегда пустые, а «Инструменты», «Самолёты»,
  «Мотоциклы», «Корабли» отфильтровать нельзя.
- **Как воспроизвести:** в подборщике нажать «skins»/«configs»/«mods» — «Ничего не нашлось»
  (`/api/mods?cat=skins` → total 0 и т.д.); при этом в каталоге 3 инструмента, 2 самолёта,
  2 мотоцикла и 1 корабль.
- **Ожидаемое поведение:** чипы = реальные категории каталога, подписи локализованы.
- **Важность:** minor.

### 11. Выход из аккаунта оставляет форму сборки открытой

- **Экран:** Сборки.
- **Что не так:** `_coll_form` хранится в состоянии `App` (`core/tkui.py:1630-1649`), `logout`
  его не сбрасывает, а `render_collections` снова рисует форму (`core/tkui.py:1556-1557`).
- **Как воспроизвести:** Сборки → «＋ Создать сборку» → меню аккаунта → «Выйти»: форма «Новая
  сборка» с полями остаётся, хотя пользователь разлогинен; «Сохранить» вернёт ошибку 401.
- **Ожидаемое поведение:** при выходе форма закрывается (или блокируется с подсказкой «войдите»).
- **Важность:** minor.

### 12. Отметка «✓ установил» не персональная и ставится за частичную установку

- **Экран:** отзывы.
- **Что не так:** `social.has_installed` (`core/social.py:251-258`) игнорирует `user_id`: для мода
  смотрит локальную библиотеку, для сборки — `bool(plan['installed'])`, т.е. «стоит хотя бы один
  мод». Отметка ставится при сохранении оценки и не обновляется.
- **Как воспроизвести:** в сборке «Дрифт по-русски» установлен 1 мод из 4 — оба отзыва разных
  авторов помечены «✓ установил» (`qa/tkui-reviews.png`); новый email-аккаунт без установок
  при оценке получил `installed=1` (ответ `/api/reviews`).
- **Ожидаемое поведение:** «установил» — только когда пользователь поставил всю сборку (или
  явная формулировка «есть в библиотеке»).
- **Важность:** minor.

### 13. `GET /api/search/log` отдаёт 500, `POST` — 404; «рекомендации по поискам» не работают

- **Экран:** API; влияет на `/api/recommend/mods` без `id`.
- **Что не так:** обработчик объявлен в `_platform_get` и использует `body`, определённый только
  в `do_POST` (`app.py:777-787`): GET → `500 {"ok":false,"error":"name 'body' is not defined"}`,
  POST → 404. Ни `web/app.js`, ни `core/tkui.py` этот маршрут не вызывают, поэтому
  `recent_searches` никогда не пополняется, а рекомендации «по поискам»
  (`core/recommend.py:98-108`) всегда работают только по библиотеке/избранному.
- **Как воспроизвести:** `GET /api/search/log` с токеном интерфейса → 500; `POST` → 404.
- **Ожидаемое поведение:** рабочий POST-эндпоинт, который вызывает поиск в UI; либо маршрут удалён.
- **Важность:** minor.

### 14. Кривые числовые query-параметры → 500 с текстом исключения

- **Экран:** API.
- **Что не так:** `int(...)` без проверки (`app.py:377-378`, `687`, `693-694`, `792`, `801`).
- **Как воспроизвести:** `/api/mods?offset=abc`, `/api/mods?limit=abc`,
  `/api/collections?limit=abc`, `/api/collections?offset=abc`,
  `/api/recommend/mods?limit=abc` → `500 {"error":"invalid literal for int() with base 10: 'abc'"}`.
- **Ожидаемое поведение:** 400 с понятной ошибкой или значения по умолчанию.
- **Важность:** minor.

### 15. `py app.py --diagnose` падает и вешает процесс

- **Экран:** CLI, режим диагностики.
- **Что не так:** в `main()` используется имя `desktop`, которого нет в модуле
  (`app.py:1357`; импортируется `appwindow`, а не `desktop`). В реальном запуске исключение
  уходит в `show_error` → модальный `MessageBoxW`, и процесс ждёт нажатия (проверено: процесс
  пришлось снимать принудительно).
- **Как воспроизвести:** `python app.py --diagnose` → `NameError: name 'desktop' is not defined`
  сразу после строки `frozen`.
- **Ожидаемое поведение:** режим печатает состояние (frozen, appwindow, webview) и выходит.
- **Важность:** minor.

### 16. «Удалить и закрыть» на жалобе о сборке не удаляет сборку

- **Экран:** модерация.
- **Что не так:** `_remove_target` для collection только снимает с публикации
  (`core/moderation.py:123-128`), а кнопка называется «Удалить и закрыть» (`core/tkui.py:2145-2148`).
- **Как воспроизвести:** жалоба на сборку → «Удалить и закрыть»: в temp-базе строка остаётся
  (`published=0`), для других пользователей страница отдаёт 404 «Сборка ещё не опубликована»,
  автор может опубликовать её снова.
- **Ожидаемое поведение:** либо кнопка называется «Снять с публикации», либо сборка удаляется.
- **Важность:** minor.

### 17. Нет склонения числительных

- **Экран:** сборки, страница сборки, отзывы, обновления, статистика.
- **Что не так:** числа подставляются без формы слова: «2 сборок», «3 сборок», «241 просмотров»,
  «2 оценок», «2 комментариев», «1 обновлений», «4 модов».
- **Как воспроизвести:** посмотреть шапку «Сборки», страницу сборки и экран отзывов
  (`qa/tkui-collection-page.png`, `qa/tkui-reviews.png`).
- **Ожидаемое поведение:** «2 сборки», «241 просмотр», «2 оценки», «2 комментария», «1 обновление».
- **Важность:** minor.
