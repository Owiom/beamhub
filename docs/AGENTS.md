# Агенты BeamHub

Постоянный состав. Прежние разовые агенты («QA v1», «Дизайн v2» и т. п.) больше не используются —
их задачи перешли к ролям ниже. Каждая итерация проходит один и тот же цикл:

```
QA-аудитор  →  Дизайнер  →  Релиз-менеджер  →  я (сборка и выпуск)
```

## 1. QA-аудитор

**Когда:** перед каждой сборкой, после любых правок интерфейса или данных.

**Что делает:**
- запускает приложение на временной базе (`BEAMHUB_DB` в `%TEMP%`), свободные порты 9200+;
- проходит все экраны: каталог, сборки (все вкладки, страница сборки, подбор мода),
  библиотека, обновления, загрузки, настройки, профиль, статистика, админ-панель, отзывы;
- проверяет кнопки: каждая либо работает, либо её нет;
- фиксирует замеры (размеры, переполнение, новые окна, исключения) и повторяет прогон;
- пишет `docs/QA-REPORT.md`: дефект, экран, воспроизведение, ожидание, важность.

**Правила:** `core/` и `app.py` не меняет; после себя удаляет пробы и процессы.

**Формат ответа:** `{critical, major, minor, regressions[], fixed[]}`.

## 2. Дизайнер

**Когда:** после QA, если есть визуальные дефекты или новые экраны.

**Что делает:**
- правит только визуальную часть: `core/theme.py` и цвета/шрифты/отступы/компоновку в `core/tkui.py`;
- проверяет, что приложение стартует, каталог рисуется, скриншот свежий;
- обязательно прогоняет `ast.parse`, `tools/lint_claims.py`, `tests/test_platform.py`;
- описывает изменения в `docs/DESIGN-2026.md`.

**Запрещено:** менять логику, API, схему БД; ломать существующие вызовы.

## 3. Релиз-менеджер

**Когда:** после дизайнера, перед публикацией.

**Что делает:**
- сверяет версию в `core/version.py` с тегом и README;
- запускает весь набор тестов и линтер;
- собирает `py build_exe.py --onedir`, проверяет, что exe стартует и отдаёт `/api/ping`;
- проверяет, что в архив попали README, docs, supabase;
- возвращает `{tests, lint, version, build_ok, notes[]}`.

## 4. Контент-редактор

**Когда:** при работе с официальными подборками и текстами.

**Что делает:**
- проверяет официальные сборки: 10 модов, без торрентов, без битых записей;
- следит за честностью формулировок (линтер);
- предлагает темы подборок под СНГ-аудиторию (Форсаж, JDM, русские машины, карты).

## Правила версий

- микро: `0.13.3 → 0.13.4 … 0.13.20`;
- после 20 — минор: `0.13.20 → 0.14.0`;
- мажор `1.0.0` — только когда QA-отчёт чистый и план из `ROADMAP-CIS.md`
  закрыт хотя бы по этапам 1–2.

## Запуск цикла

Цикл оформляется как workflow из двух-трёх агентов (QA → дизайн → релиз).
Результат каждого агента сохраняется в `docs/`, а сборка выпускается только
после зелёного отчёта релиз-менеджера.
